## Actual worker demonstration

Use this bounded packet in two isolated proposal directories at the same baseline:

> Implement `ordered_unique(items)` in Python. Return a list preserving first occurrence order. Accept hashable and unhashable values using normal equality; do not mutate the input; support generators and empty input; use only the standard library. Add tests. Return a concise result and artifact references. Do not modify files outside the assigned directory.

Before seeing either result, define mandatory gates: correct order, duplicate removal, unhashable inputs, generator input, empty input, no mutation, no third-party dependencies, and all tests passing. Score correctness 60, test coverage 25, and maintainability 15; require all gates and at least 80/100. The coordinator runs independent checks as well as candidate tests.

1. Discover two eligible remote profiles. Hold thinking, prompt, tools, baseline, and evaluator fixed. Run one model comparison. Review candidate artifacts with model identity and cost concealed.
2. Record actual outcomes, including failures. Show the report. If either usage or pricing is missing, show cost as unavailable. Count coordinator review and experimental overhead separately.
3. For the selected model, use another small packet to compare two supported thinking settings, with all other variables held constant. Do not recycle the same answer into later workers.
4. Run a subsequent comparable task, asking the coordinator to use the accumulated evidence. Show whether it selects a proven route or correctly keeps evidence provisional.
5. Export aggregate learning, dry-run import into another temporary project, apply it, then perform local verification. A failed verification should quarantine the prior for that environment.

A single bakeoff need not establish a preferred route. Explain the actual promotion state rather than promising that every demonstration creates a recommendation. Preserve rejected results as part of experiment overhead.
