# Active routing and recovery validation: 1.3.0-rc.6

RC6 routes eligible work through Jev immediately after project setup. No qualification certificate, minimum sample count, or routing shadow stage gates use. This development trial verifies the workflow; it does not establish population reliability, optimal model selection, security quality, or savings.

The machine-readable artifact is [active-recovery-results.json](active-recovery-results.json). Twelve real repository task cards covered review, tests, and bounded fixes. The eligible Luna fallback fixed it, added regressions, and passed independent review. Failed observations and the coordinator error remain recorded. Automated browser visual inspection of the local HTML was blocked by the browser URL policy; report structure, content and escaping are covered by tests.

These simulated events remain separate from native outcomes.

## Boundaries and use

Python prepares and validates execution plans; the coordinator invokes native Codex workers and reviews their results. Model revisions identify advertised host settings, not immutable weights. Tool permissions and isolated copies are cooperative controls, not a new sandbox. Credentials are read-only. Artifact sharing is separate from routing-summary permission, and optional judging remains advisory.

The local HTML/JSON trial report includes explicitly selected task descriptions. Ordinary reports remain metadata-only; use `report --task-descriptions descriptions.json` to opt into readable local descriptions. Rebuild archives with `scripts/build_release.py` and the Yarn agent package with `scripts/build_yarn_handoff.py`. The Yarn package contains setup and recovery instructions, not results from a Yarn consolidation. Neither the installed skill nor a published release is modified automatically.
