# Yarn handback acceptance worksheet

Fill from actual repository evidence. Unchecked means pending, not passed.

- [ ] Both source versions located and exact refs recorded; unrelated edits preserved.
- [ ] Feature/behavior reconciliation agreed or unresolved product choices listed.
- [ ] Unified app slice builds and its documented user flow works.
- [ ] Regression checks cover retained behavior from both source versions.
- [ ] Persistence/interface migration, if needed, has explicit validation and recovery handling.
- [ ] Delegation integration uses an actual supported host boundary; unsupported runtime dispatch is explicit.
- [ ] Missing Jev/key/Python or unavailable routing has a usable, honest application state.
- [ ] Default routing/sharing/security settings respect the project configuration.
- [ ] No credential creation/update/deletion, logging, client exposure or argv transmission.
- [ ] Prepared packet preview, exact candidate discovery and dispatch recheck exercised.
- [ ] No stale/synthetic packet executed; task risk, tools and capacity checks preserved.
- [ ] Independent quality review and mandatory gates recorded for real worker outputs, including failures.
- [ ] At least one actual baseline/challenger comparison recorded, or comparison pending with the specific reason.
- [ ] HTML/JSON report regenerated from actual ledger and manually inspected.
- [ ] Unknown costs, unfinished tasks, limited security coverage and unqualified thresholds remain explicit.
- [ ] Optional advisory security disabled initially; if enabled, failure does not break normal recording.
- [ ] Remaining consolidation work, bugs and limitations listed; no premature completion claim.

Record for each task group: source refs, acceptance contract, worker/configuration identity, review identity, artifact hash, commands/results, review dimensions, security status, measured/estimated/unknown costs, latency and report location. Keep raw source and detailed review notes within the project; only explicit sanitized projections go to Jev.
